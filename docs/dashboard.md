# Dashboard

The web dashboard is a single-page UI for controlling Waver from any device
on the LAN. Source: [dashboard/](../dashboard).

It is served as static files by Flask, and talks to the [API](api.md) over
fetch + SocketIO.

---

## Access

```
https://192.168.0.191/       # IP
https://waver.local/         # mDNS, if avahi is up
https://10.0.0.1/            # via WireGuard tunnel
```

Plain HTTP on port 80 redirects to HTTPS. First visit will show a
"connection is not private" warning — that's expected, the cert is
self-signed. Click through, or trust the cert per-device once
([details below](#https)).

Login with the password whose bcrypt hash is in `api/config.py`. The JWT
returned is stored in `localStorage` and attached to every subsequent
request.

- One-click toggle for Pi-hole and WireGuard

## HTTPS

The dashboard is served over HTTPS using a self-signed certificate
generated at install time. See [setup.md](setup.md#8-tls-certificate)
for the cert generation step.

### Cert details

- **Location on the Pi:** `/etc/ssl/waver/waver.crt` + `waver.key`
- **Generated by:** [config/scripts/gen-cert.sh](../config/scripts/gen-cert.sh)
- **SANs:** `waver`, `waver.local`, `localhost`, `127.0.0.1`,
  `192.168.0.191`, `10.0.0.1`
- **Validity:** 10 years
- **Re-issue:** `sudo bash gen-cert.sh --force`

### Trusting the cert per-device (optional)

Click-through-the-warning works fine on every visit, but if you want
the green padlock and no warning, copy the cert off the Pi once and
import it as trusted:

```bash
scp cimi@waver.local:/etc/ssl/waver/waver.crt ~/Downloads/
```

Then on each device:

| Platform | Where to import                                                    |
|----------|---------------------------------------------------------------------|
| macOS    | Keychain Access → System → drag in the .crt → set to *Always Trust* |
| iOS      | AirDrop the .crt → install profile → Settings → General → About → Certificate Trust Settings → enable |
| Windows  | Right-click .crt → Install Certificate → Local Machine → Trusted Root Certification Authorities |
| Linux    | `sudo cp waver.crt /usr/local/share/ca-certificates/ && sudo update-ca-certificates` |
| Firefox  | Settings → Privacy & Security → Certificates → View Certificates → Authorities → Import |
| Android  | Annoying — modern Android only trusts user certs for some apps; plan to click-through |

The trust step is per-browser on Firefox (separate cert store) and
sometimes per-app on Android.

## Reverse proxy

nginx terminates HTTPS on port 443 and proxies everything to Flask on
`127.0.0.1:5000`. A second `location` block proxies `/pihole/` to the
Pi-hole admin UI on port 8080. Plain HTTP on `:80` issues a 301 redirect
to HTTPS.

[config/nginx/waver.conf](../config/nginx/waver.conf):

```nginx
# Redirect plain HTTP to HTTPS
server {
    listen 80;
    server_name waver.local 192.168.0.191 _;
    return 301 https://$host$request_uri;
}

# Waver dashboard + API over HTTPS
server {
    listen 443 ssl http2;
    server_name waver.local 192.168.0.191 _;

    ssl_certificate     /etc/ssl/waver/waver.crt;
    ssl_certificate_key /etc/ssl/waver/waver.key;

    ssl_protocols              TLSv1.2 TLSv1.3;
    ssl_ciphers                HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers  off;

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }

    location /pihole/ {
        proxy_pass http://127.0.0.1:8080/;
        proxy_set_header Host              $host;
        proxy_set_header X-Forwarded-Proto https;
    }
}
```

> **No** `Upgrade` / `Connection` headers. Adding them caused SocketIO
> connections to hang during the initial handshake. Plain proxying works
> fine — gevent-websocket handles the upgrade itself.

## Auth flow

1. User enters password in the login form.
2. `app.js` POSTs to `/api/auth/login`, gets a JWT back.
3. Token saved to `localStorage` under a fixed key.
4. All subsequent fetches include `Authorization: Bearer <token>`.
5. SocketIO connects with `{ auth: { token } }` in the handshake.
6. Logout clears `localStorage` and reloads the page.

If a request returns 401, the client drops the token and bounces back to
the login screen.

---

## Live updates

The dashboard polls `/api/system/status` on an interval for things that
don't have a push channel (uptime, temp). Service toggles use SocketIO:
when any client toggles Pi-hole, the API emits `service_update` and every
connected dashboard updates its badge without polling.

## Editing the dashboard

```bash
ssh cimi@waver.local
cd ~/waver/dashboard
nano index.html        # or pull and edit locally, push, OTA update
```

No restart needed — Flask serves the files directly from disk on each
request. Hard-refresh (`Ctrl-Shift-R`) to bypass browser cache.
